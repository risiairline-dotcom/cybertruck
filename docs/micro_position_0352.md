# GC-BASE-0.3.52 候选：底盘位置模式微调与航向修正

用户要求对位继续走底盘微调，不用转臂补偿（转臂风险大）；粗停后可能带航向偏差，而夹爪中心与车体中心在 Y 方向不重合，航向误差会在夹爪处变成横向误差。L2 转臂对中（PR #4）暂停，不合并。

## 改动

- **小步执行方式**：配置10的每个小步改由驱动器执行 FD 相对位置命令（模式02，相对当前实时位置，acc=0，不同步）。四轮同幅，平移2RPM、纯转向1RPM。原先的"低RPM定时速度脉冲"位移取决于死区和启停滞后，+Y 实物未通过；位置模式按驱动器自身编码器走完指定脉冲。
- **航向先修**：每步先看航向误差（容差0.2°），超出就先出纯转向小步，再走平移。新增配置10纯转向目标：kind=2，0.1°～3°，以当前航向加转角重设本会话的目标航向；平移目标沿用会话航向，不把残余偏航当成新零点。
- **执行期间**：不发任何速度命令（零速也不发，否则会打断 FD）；35/36 反馈查询照常，250ms 反馈过期保护不变。
- **释放条件**：四轮 FD 整批 TXOK 后开始计时；估算时间到、静止的新反馈、且里程计显示已沿指令方向走过至少一半，才发零速并进入150ms稳定窗口。驱动器起步迟滞时不会提前用零速打断尚未开始的小步。
- **超时**：TXOK 前超过250ms，或 TXOK 后超过估算时间×3+500ms 仍未完成，均按超时停车，不重发。
- **单步上限**：轮缘位移6mm（3°纯转向在0.204m杠杆上约10.7mm，会分两步）。
- **脉冲换算**：每轮脉冲/圈 = 整步数（0x19→200，0x32→400）× 驱动器细分，取自读回的 0x42 配置。配置10下缺配置时，空闲轮询先逐轮补读 0x42；四轮读齐前不准备 PC0、不点火。Pi 在配置10生效后等0.4秒再请求 PC0 准备。
- **Pi**：`alignment_step` 支持 `axis='yaw', deg=±0.1～3`（需0.3.52）；自动对中可带 `yaw_correction_deg`（±3°，逆时针为正，由任务层或人工给出），先转到修正后的航向（0.3°以内）再看圆环；偏离超过3.2°暂停。网页微调面板加了转向按钮和航向修正输入。

## 验证（仅离线）

- 主机回归：`tools/test.ps1`。真实 C Track/Exec + 合成车体：X/Y ±1/±5mm、转向 ±0.5/±3°均完成；120/160/200ms 轮询 × 0.08/0.2/0.35s 响应；缺 TXOK、缺零速 TXOK、车轮堵转、单轮卡死、反馈丢失、起步迟滞100/300/600ms。
- 板级夹具（正式 base_port/Bus/CAN）：0x42 补读、32脉冲换算、整批 TXOK 后才确认、速度快照取代未发出的小步时不确认。
- Keil 0 错误 0 警告。HEX SHA256 `dd76cb5a293218ff358cdd3c8b0d1d5f720a98c7f567c650a990b4dd658eddfb`，未烧录。

## 未验证

- 驱动器 FD 模式02在本车四轮上的实际方向、到位精度及到位后保持；轮子与地面打滑只能靠 IMU 航向和视觉复核发现。
- 0x42 读回的细分值是否与驱动器实际设置一致（离线夹具假设16细分）。
- `yaw_correction_deg` 的来源：任务层尚未计算站位朝向与粗停航向之差，目前由人工填写。

## 现场顺序（须本次烧录后用户确认放地并允许实测）

1. 烧录后只读确认版本 0.3.52、四轮 0x42 配置读齐、故障0。
2. 手动模式：转向 +0.5°、−0.5°各一次，核对 IMU 航向变化与方向；再 +Y 1mm、−Y 1mm，尺量实际位移。
3. 方向与比例确认后再试 5mm 与 3°，记录步数与耗时，确认单次对中能在15秒停滞规则内完成。
